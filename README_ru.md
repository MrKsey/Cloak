# Cloak (Оптимизированный форк)

[![Build and test](https://github.com/MrKsey/Cloak/actions/workflows/build.yml/badge.svg)](https://github.com/MrKsey/Cloak/actions)
[![Release](https://github.com/MrKsey/Cloak/actions/workflows/release.yml/badge.svg)](https://github.com/MrKsey/Cloak/releases)

Cloak — это [подключаемый транспорт](https://datatracker.ietf.org/meeting/103/materials/slides-103-pearg-pt-slides-01), который улучшает традиционные прокси-инструменты (Shadowsocks, OpenVPN и др.) для обхода сложной цензуры и систем глубокого анализа пакетов (DPI).

Это **оптимизированный форк** [cbeuw/Cloak](https://github.com/cbeuw/Cloak), ориентированный на повышение пропускной способности и снижение задержек за счёт целевых оптимизаций производительности.

---

## Оптимизации производительности

Этот форк реализует несколько ключевых оптимизаций, значительно повышающих скорость:

### 1. Устранены системные вызовы `crypto/rand` для каждого кадра
Оригинальный код вызывал `crypto/rand.Read` для каждого кадра — дорогой системный вызов. Этот форк заменяет его пулом генераторов ChaCha8 (по одному на горутину), инициализированных криптографической случайностью, что исключает системные вызовы в горячем пути без потери безопасности.

### 2. Пропущена ненужная генерация случайных байтов для шифрованных кадров
При включённом AEAD-шифровании последние байты случайной области перезаписываются тегом аутентификации AEAD. Оригинальный код генерировал случайные байты, которые тут же уничтожались. Этот форк генерирует случайные байты только когда они действительно нужны (паддинг для первых 5 кадров или nonce для режима plain).

### 3. Пул буферов для копирования соединений
Функция `Copy` теперь использует `sync.Pool` для буфера 32 КиБ вместо выделения памяти при каждом вызове, что снижает нагрузку на сборщик мусора при большом количестве одновременных соединений.

### 4. Исправлен размер буфера записи TLS
Увеличена ёмкость пула буферов записи TLS-соединения до максимального размера TLS-записи (RFC 8446 §5.2), что устраняет реаллокации буферов для больших кадров.

### Результаты бенчмарков

Улучшение пропускной способности обфускации (кадры 1 КиБ, однопоточно):

| Шифрование | Оригинал | Оптимизировано | Ускорение |
|---|---|---|---|
| plain | 1 699 МБ/с | 4 065 МБ/с | **2.4x** |
| AES-128-GCM | 1 103 МБ/с | 1 864 МБ/с | **1.7x** |
| AES-256-GCM | 1 034 МБ/с | 1 665 МБ/с | **1.6x** |
| ChaCha20-Poly1305 | 831 МБ/с | 1 174 МБ/с | **1.4x** |

Сквозные интеграционные улучшения (кадры 16 КиБ):

| Шифрование | Оригинал | Оптимизировано | Улучшение |
|---|---|---|---|
| plain | 1 710 МБ/с | 1 818 МБ/с | +6.3% |
| AES-128-GCM | 1 395 МБ/с | 1 500 МБ/с | +7.5% |
| ChaCha20-Poly1305 | 876 МБ/с | 1 016 МБ/с | +15.9% |

Задержка снижена на 9-35% для всех методов шифрования.

### Улучшения стабильности сессий

- **Настраиваемый `SessionIdleTimeout`** (клиент и сервер): контролирует, сколько сессия живёт без активных потоков до закрытия. Раньше было захардкожено 30 секунд, что вызывало частую ротацию сессий и повторные TLS-рукопожатия (более заметные для DPI). По умолчанию теперь 300 секунд (5 минут).
- **Исправлен баг `KeepAlive` на клиенте**: параметр `KeepAlive` в конфиге клиента молча игнорировался из-за ошибки умножения. Теперь применяется корректно, с разумным значением по умолчанию 30 секунд, если не задан.

## Сборка

### Из исходников

```bash
git clone https://github.com/MrKsey/Cloak
cd Cloak
go get ./...
make
```

Готовые бинарники будут в папке `build`.

### Кросс-компиляция

```bash
# Linux amd64
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -ldflags "-s -w" ./cmd/ck-client
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -ldflags "-s -w" ./cmd/ck-server

# Linux arm64
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -trimpath -ldflags "-s -w" ./cmd/ck-client
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -trimpath -ldflags "-s -w" ./cmd/ck-server

# Windows amd64
CGO_ENABLED=0 GOOS=windows GOARCH=amd64 go build -trimpath -ldflags "-s -w" ./cmd/ck-client
CGO_ENABLED=0 GOOS=windows GOARCH=amd64 go build -trimpath -ldflags "-s -w" ./cmd/ck-server
```

### Готовые бинарники

Скачайте последний релиз для вашей платформы со страницы [Releases](https://github.com/MrKsey/Cloak/releases).

Доступные сборки:
- `ck-client-linux-amd64`
- `ck-client-linux-arm64`
- `ck-client-windows-amd64.exe`
- `ck-server-linux-amd64`

## Конфигурация

Примеры конфигурационных файлов находятся в папке `example_config`.

### Сервер

`RedirAddr` — адрес перенаправления, когда входящий трафик не от клиента Cloak. Желательно крупный сайт, разрешённый цензором (например, `www.bing.com`).

`BindAddr` — список адресов, которые Cloak будет слушать (например, `[":443",":80"]`).

`ProxyBook` — объект, ключ которого — имя ProxyMethod на стороне клиента (чувствительно к регистру). Значение — массив: первый элемент — протокол, второй — `IP:PORT` вышестоящего прокси-сервера.

Пример:
```json
{
  "ProxyBook": {
    "shadowsocks": ["tcp", "localhost:51443"],
    "openvpn": ["tcp", "localhost:12345"]
  }
}
```

`PrivateKey` — статический приватный ключ curve25519 Diffie-Hellman в base64.

`BypassUID` — список UID, авторизованных без ограничений по полосе пропускания и кредиту.

`AdminUID` — UID администратора в base64. Оставьте пустым, если используете только `BypassUID`.

`DatabasePath` — путь к `userinfo.db` для хранения информации о пользователях. Оставьте пустым, если используете только `BypassUID`.

`KeepAlive` — секунды TCP KeepAlive для соединения с вышестоящим прокси. `0` использует разумное значение по умолчанию (30 с); отрицательное значение отключает. По умолчанию: 30.

`SessionIdleTimeout` — сколько секунд сессия остаётся открытой без активных потоков, прежде чем закрыться. Большее значение снижает частоту новых TLS-рукопожатий (которые более заметны для DPI). `0` использует разумное значение по умолчанию. По умолчанию: 300 (5 минут).

### Клиент

`UID` — ваш UID в base64.

`Transport` — `direct` или `CDN`.

`PublicKey` — статический публичный ключ curve25519 в base64, выдаётся администратором сервера.

`ProxyMethod` — должен совпадать с одной из записей в `ProxyBook` сервера.

`EncryptionMethod` — `plain`, `aes-256-gcm`, `aes-128-gcm` или `chacha20-poly1305`. **Используйте `plain` только если ваш прокси уже обеспечивает шифрование и аутентификацию.**

`ServerName` — домен, который ваш провайдер должен «видеть». Используйте `random` для случайного выбора при каждом соединении.

`AlternativeNames` — массив доменов для чередования при каждом новом соединении.

`CDNOriginHost` — домен origin-сервера в режиме CDN. Действует только при `Transport: CDN`.

`CDNWsUrlPath` — URL-путь для WebSocket-запросов в режиме CDN. По умолчанию `/`.

`NumConn` — количество базовых TCP-соединений. По умолчанию: 4. Установите 0 для режима singleplex.

`BrowserSig` — эмулируемая сигнатура браузера: `chrome`, `firefox` или `safari`.

`KeepAlive` — секунды TCP KeepAlive для соединения с сервером Cloak. `0` использует разумное значение по умолчанию (30 с); отрицательное значение отключает. По умолчанию: 30.

`StreamTimeout` — секунды ожидания первого байта данных от входящего соединения перед закрытием. По умолчанию: 300.

`SessionIdleTimeout` — сколько секунд сессия остаётся открытой без активных потоков, прежде чем закрыться. Большее значение снижает частоту новых TLS-рукопожатий (которые более заметны для DPI). `0` использует разумное значение по умолчанию. По умолчанию: 300 (5 минут).

## Настройка

### Настройка сервера

1. Установите хотя бы один прокси-сервер (например, OpenVPN, Shadowsocks).
2. Скачайте [последний релиз](https://github.com/MrKsey/Cloak/releases) или соберите из исходников.
3. Выполните `ck-server -key`. **Публичный** ключ — пользователям, **приватный** — храните в секрете.
4. (Пропустите, если только unrestricted-пользователи) Выполните `ck-server -uid` для генерации `AdminUID`.
5. Скопируйте `example_config/ckserver.json`. Установите `PrivateKey` и `AdminUID`.
6. Настройте прокси-серверы слушать на localhost. Отредактируйте `ProxyBook`.
7. Запустите `sudo ck-server -c <путь к ckserver.json>`.

#### Добавление пользователей

**Unrestricted-пользователи:** Выполните `ck-server -uid` и добавьте UID в `BypassUID`.

**Пользователи с ограничениями полосы/кредита:**
1. Убедитесь, что `AdminUID` и `DatabasePath` установлены в `ckserver.json`.
2. На клиенте выполните `ck-client -s <IP> -l <локальный-порт> -a <AdminUID> -c <путь-к-ckclient.json>` для входа в режим администратора.
3. Откройте [Cloak-panel](https://cbeuw.github.io/Cloak-panel) для управления пользователями.

### Настройка клиента

1. Установите прокси-клиент, соответствующий серверу.
2. Скачайте [последний релиз](https://github.com/MrKsey/Cloak/releases) или соберите из исходников.
3. Получите публичный ключ и UID у администратора сервера.
4. Скопируйте `example_config/ckclient.json`, введите `UID` и `PublicKey`. Установите `ProxyMethod` в соответствии с `ProxyBook` сервера.
5. Запустите `ck-client -c <путь-к-ckclient.json> -s <IP-сервера>`.
